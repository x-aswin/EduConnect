### Flow

**College side:**
1. College marks course as `is_certified = true` and adds 1–3 signatories (name, designation, signature image) when creating/editing the course.
2. After the course end_date passes (or manually), college sees a "Mark Certificates Available" action on confirmed enrollments — sets `certificate_issued = true` and generates `certificate_code` (e.g. `Str::uuid()` or a short hash like `strtoupper(Str::random(10))`).

This can be bulk — a button on the course's enrollment list: "Issue Certificates to All Confirmed Students" → loops through confirmed enrollments, sets the flag.

**Student side:**
1. On "My Enrollments" page, if `enrollment.certificate_issued == true`, show a "Download Certificate" button.
2. Clicking it hits a route like `/student/enrollments/{enrollment}/certificate` → controller generates PDF on-the-fly using student name, course title, college name, dates, and the signatories — returns as download (not stored).

### PDF Generation

Use the `pdf` skill / a library like `barryvdh/laravel-dompdf` or `dompdf` directly — render a Blade view (`certificates.student`) to HTML, convert to PDF, stream it.

```php
public function downloadCertificate(Enrollment $enrollment)
{
    abort_unless($enrollment->user_id === auth()->id(), 403);
    abort_unless($enrollment->certificate_issued, 404);

    $enrollment->load(['course.college', 'course.signatories', 'user']);

    $pdf = Pdf::loadView('certificates.student', [
        'enrollment' => $enrollment,
    ]);

    return $pdf->stream('certificate-' . $enrollment->certificate_code . '.pdf');
}
```

The certificate blade includes student name (`enrollment.user.name`), course title, college name, dates, "Certified" badge if applicable, and loops through up to 3 signatories rendering signature image + name + designation side by side.

### Verification Link

You suggested `?q=userid_courseid_enrollmentid` — better to use the single `certificate_code` (random unique string) instead. Reasons:

- A guessable composite of sequential IDs lets anyone enumerate certificates (`?q=1_1_1`, `?q=1_1_2`...) — privacy/security issue.
- A random unique code per certificate is the standard approach and simpler to verify.

```
https://educonnect.test/verify-certificate/{certificate_code}
```

Public route, no auth required:

```php
public function verify(string $code)
{
    $enrollment = Enrollment::where('certificate_code', $code)
        ->where('certificate_issued', true)
        ->with(['course.college', 'user'])
        ->first();

    return view('certificates.verify', compact('enrollment'));
}
```

The verify page shows: "This certificate is valid" with student name, course, college, issue date — or "Certificate not found / invalid" if null. Don't expose sensitive info beyond what's already on the certificate itself.

### QR Code on Certificate (nice addition)

Embed a QR code on the PDF pointing to the verification URL — easy with `simplesoftwareio/simple-qrcode`, lets anyone scan and verify instantly.

## Controller — `issue()`

```php
public function issue(Request $request, Course $course)
{
    abort_unless($course->college_id === auth()->user()->college->id, 403);

    $request->validate([
        'signatories' => 'required|array|min:1|max:3',
        'signatories.*.name' => 'required|string|max:255',
        'signatories.*.designation' => 'required|string|max:255',
        'signatories.*.signature_image' => 'nullable|image|mimes:png,jpg,jpeg|max:1024',
        'signatories.*.existing_image' => 'nullable|string', // hidden field for unchanged images
    ]);

    DB::transaction(function () use ($request, $course) {
        // Clear and re-save signatories
        foreach ($request->signatories as $index => $sigData) {
            $imagePath = $sigData['existing_image'] ?? null;

            if ($request->hasFile("signatories.$index.signature_image")) {
                $imagePath = $request->file("signatories.$index.signature_image")
                    ->store('signatures', 'public');
            }

            CertificateSignatory::updateOrCreate(
                ['course_id' => $course->id, 'display_order' => $index + 1],
                [
                    'name' => $sigData['name'],
                    'designation' => $sigData['designation'],
                    'signature_image' => $imagePath,
                ]
            );
        }

        // Issue certificates to all confirmed enrollments for this course
        Enrollment::where('course_id', $course->id)
            ->where('status', 'confirmed')
            ->where('certificate_issued', false)
            ->update([
                'certificate_issued' => true,
                'certificate_issued_at' => now(),
                'certificate_code' => null, // generated lazily, see note below
            ]);
    });

    return redirect()->route('college.certificates.index')
        ->with('success', 'Certificates issued for ' . $course->title);
}
```

## On `certificate_code` Generation

Don't generate it here in a loop with `Str::random()` — collisions are unlikely but possible, and you'd need to check uniqueness per row. Instead, generate it lazily the first time the student downloads (or verifies):

```php
// In the student download controller
if (!$enrollment->certificate_code) {
    $enrollment->update(['certificate_code' => strtoupper(Str::random(10))]);
}
```

This also means re-issuing (if a college re-runs "issue" for newly confirmed enrollments) won't touch already-issued ones — the `where('certificate_issued', false)` guard handles that.
